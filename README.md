# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

전 세계 기상 관측 데이터를 제공하는 Open-Meteo 외부 공개 API를 React와 연동하여 구축한 **실시간 날씨 및 대기질 모니터링 반응형 대시보드**입니다.  
Google Antigravity IDE를 활용하여 단계별 구현 계획(Implementation Plan) 수립, 컴포넌트 모듈화, 사이버보안 아키텍처 점검 및 나만의 커스터마이징 기능까지 완비했습니다.

---

## 소개

- **주요 도시 원클릭 조회**: 서울(강서), 서울(시청), 인천, 부산, 대구, 대전, 광주, 제주 등 8대 프리셋 도시 빠른 선택
- **실시간 날씨 상세 카드**: 실시간 기온, 체감온도, 상대습도, 풍속, 강수량 및 WMO 코드 기반 Lucide 동적 날씨 아이콘과 한국어 상태 안내
- **환경부 기준 미세먼지 카드**: PM10(미세먼지), PM2.5(초미세먼지) 수치, 시각적 게이지 바, 환경부 4단계(`좋음`/`보통`/`나쁨`/`매우 나쁨`) 컬러 뱃지
- **24시간 시간별 기온 차트**: `weather.hourly` 데이터를 실시간 파싱하여 현재 시점 기준 24시간 기온 추이를 보여주는 가볍고 빠른 반응형 인라인 SVG 꺾은선 차트
- **7일간 주간 날씨 예보**: `weather.daily` 데이터를 활용한 일별 최고/최저 기온, 강수 확률(%), 주간 기온 범위 바 시각화
- **실시간 도시 검색 & 400ms 디바운스**: 국내외 전 세계 도시 검색 및 자동완성 드롭다운 (DoS/429 오류 방어)
- **날씨 & 주야간 동적 비주얼 테마**: 맑음/비/눈/흐림/뇌우 및 낮/밤(`is_day`)에 따라 자동으로 은은하게 전환되는 6종 맞춤형 배경 그라데이션
- **최근 조회 도시 보관**: `localStorage` 연동으로 최근 검색/선택한 도시를 최대 5개까지 칩 형태로 보관하고 원클릭 재조회 지원

## 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo API의 특징**:  
  Open-Meteo는 별도의 API Secret Key 발급이나 회원가입 없이 클라이언트 브라우저에서 직접 HTTPS로 호출할 수 있는 완전 공개(Public) 기상 데이터 서비스입니다.
- **UI 컴포넌트와 API 통신 로직(`src/api/weather.js`)의 분리 이유**:  
  관심사의 분리(Separation of Concerns) 원칙을 적용하여, UI 렌더링 로직(`App.jsx`, 컴포넌트들)과 네트워크 통신 및 데이터 가공 로직(`weather.js`)을 독립적으로 분리했습니다. 이를 통해 엔드포인트 주소나 파라미터가 변경되더라도 UI 코드 수정 없이 API 모듈만 단독으로 유지보수할 수 있습니다.
- **디바운스(Debounce, 400ms)의 필요성**:  
  도시 검색창에 한 글자를 입력할 때마다 즉시 API를 호출하면, 사용자가 "Seoul"을 입력하는 짧은 순간에도 5번 이상의 불필요한 HTTP 요청이 발생합니다. 이는 클라이언트 브라우저 성능을 저하시킬 뿐만 아니라, API 서버 입장에서 DoS 공격 형태의 부하가 되어 `429 Too Many Requests`(IP 차단) 제재를 유발합니다.  
  입력이 멈춘 후 400ms가 경과했을 때 단 1회만 호출하도록 디바운스를 적용하여 안전하고 효율적인 통신 환경을 구축했습니다.

## 보안에서 확인한 것 (사이버보안과 체크포인트)

- **공개 API (Public API) vs 보안 API (Private/Secret API)**:  
  Open-Meteo와 같은 공개 API는 브라우저에서 직접 요청해도 무방하지만, 결제 모듈, 사내 회원 정보, 유료 LLM API처럼 비밀 키(`secret key`)가 필요한 서비스는 **절대로 React 프론트엔드 코드에 키를 포함하거나 직접 호출해서는 안 됩니다.** 브라우저의 개발자 도구(Network 탭, Sources 탭)나 빌드된 자바스크립트 번들에서 누구나 키를 100% 탈취할 수 있어 막대한 과금 피해나 데이터 유출 사고가 발생하기 때문입니다.
- **백엔드 프록시 서버(BFF, Backend For Frontend)의 필요성**:  
  비밀 키가 필요한 보안 API의 경우, 서버 환경변수(`.env`)에 키를 안전하게 보관하는 전용 백엔드 프록시 서버를 두어야 합니다. 프론트엔드는 자체 인증 토큰을 통해 프록시 서버만 호출하고, 프록시 서버가 백엔드 내부에서 안전하게 외부 API를 호출한 뒤 결과만 정제하여 클라이언트에 전달하는 아키텍처를 구성해야 합니다.
- **HTTPS와 혼합 콘텐츠(Mixed Content) 방어**:  
  배포 사이트가 `https://` 보안 프로토콜을 사용할 때 암호화되지 않은 `http://` 엔드포인트를 호출하면 중간자 공격(Man-in-the-Middle, MitM)에 의해 기상 데이터가 위변조되거나 통신이 감청될 위험이 있습니다. 최신 브라우저는 이를 '혼합 콘텐츠(Mixed Content)'로 규정하여 통신을 원천 차단합니다. 본 프로젝트는 모든 API 엔드포인트에 HTTPS 암호화 통신을 엄격히 적용했습니다.

## 커스터마이징한 부분

1. **날씨 & 주야간(is_day) 동적 비주얼 테마 (옵션 A)**:
   - WMO 날씨 코드(맑음, 비, 눈, 흐림, 뇌우)와 `is_day`(낮=1, 밤=0) 파라미터를 결합하여 총 6종의 배경 그라데이션 테마(`.theme-day-clear`, `.theme-night-clear`, `.theme-rain`, `.theme-snow`, `.theme-cloudy`, `.theme-thunder`)를 설계했습니다.
   - 0.8초의 부드러운 CSS `transition` 애니메이션을 적용하고, 야간 및 어두운 테마 환경에서도 텍스트 가독성이 완벽히 유지되도록 고대비 타이포그래피 스타일을 적용했습니다.
2. **최근 조회 도시 localStorage 보관 및 관리 (옵션 B)**:
   - 사용자가 검색하거나 선택한 도시를 브라우저 `localStorage`에 자동으로 최대 5개까지 중복 없이 저장합니다.
   - 상단에 '최근 조회' 칩 버튼 바를 제공하여 원클릭으로 직전 도시를 다시 조회할 수 있도록 편의성을 높였으며, 언제든 기록을 초기화할 수 있는 '비우기' 버튼을 제공합니다.
